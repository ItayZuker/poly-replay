# Market

Live trading console for the selected series.

## Trade controls

| Control | Meaning |
|---------|---------|
| **Allow trade** | Off = demo; on = real orders when other gates pass. Turning **Off** also moves every Trigger card that was on **Trade** back to **Demo** |
| **Manual Override** | Per-series **Buy** and **Sell** dropdowns (`FAK` or `FOK`, default **FOK**). Used when you click the quote Buy/Sell boxes (not phase Auto Trade) |
| **Auto Trade** | Bot may trade using the active setup; label shows **· On** / **· Off** |
| **Size** | Manual / fallback order size |
| **Use Schedule** | With Auto Trade: the UTC schedule cell picks the setup; label shows **· On** / **· Off** |
| **Prediction** | Manipulation / prediction detector. Per-series switch; the label shows **· On** / **· Off**. Detects adverse UP/DOWN Buy quotes vs Gap. When **On**, the panel expands to show **Trade**, Order type, Shares, quote/Duration/Shift/Profit inputs, Trigger Area, Buy/Sell quote boxes, and Right/Wrong. When **Off**, that block collapses so only the Prediction switcher and ⓘ remain — ⓘ still opens the short info note (not the settings). **Trade** · On/Off is active only when **Allow trade** and **Prediction** are both On — turning either Off forces Trade Off and disables it. **Settings** sync per series; **triggers and scoring run only on the deployed app** (not localhost). |

| Setting | Meaning |
|---------|---------|
| **Trade** | When **On** (requires Allow trade + Prediction On): detector places a real Buy on trigger and a real Sell when Profit hits (or rests a GTD sell right after Buy when Sell is **GTD**), using Prediction **Shares** and Prediction Buy/Sell order types. Profit / Right use the **actual Buy fill** + **Profit prediction (¢)** (not the trigger Ask). **Race with phase Auto Trade** (same as Replay): from the start of the window either side may buy first; while one position is open the other cannot buy; after that position sells both may race again. When **Off**: same UI/scoring as sim (no orders) using the trigger Ask as the buy basis. Replay has no Trade switch — Prediction On implies sim trades there |
| **Order type** | Prediction Trade **Buy** `FAK` or `FOK`; **Sell** `FAK`, `FOK`, or `GTD` (defaults **FOK**). Separate from Manual Override. With Sell **GTD**, a resting limit sell is placed as soon as the Prediction Buy fills, at **fill** + **Profit prediction (¢)** — it does not wait for Bid to hit that target. Late in the window a GTD may still place but is less likely to fill before settlement |
| **Shares** | Share count for Prediction Trade buys (1–100000, default **10**). Sells use held shares |
| **Max Quote (¢)** | Max price of the cheapening Buy when Duration starts (1–99, default **90**). For Prediction DOWN that is UP Buy; for Prediction UP that is DOWN Buy |
| **Min Quote (¢)** | Min price of that cheapening Buy when Duration starts (1–99, default **70**). Must be ≤ Max Quote |
| **Duration (Sec)** | Seconds the condition must hold (compare now vs that many seconds ago) |
| **Shift (¢)** | Minimum drop of that cheapening Buy over Duration (1–50, default **5**). Example: Max Quote **80**, Shift **5** → must reach **≤ 75¢** |
| **Profit prediction (¢)** | After a Prediction buy: predicted-side **Sell** (Bid) must reach the **buy fill** (or trigger Ask when Trade is Off / buy failed) + this many ¢ sometime before window end for **Right** (1–50, default **5**). Window outcome is ignored |
| **Trigger Area** | Dual-handle bar over the market window timeline. Time labels under each handle move with the dots (`0:00` → window length, e.g. `5:00` for a 5m market). Only the span between the handles is watched |
| **Prediction** | Two half-width controls under Trigger Area (shown when Prediction is **On**): disabled **Buy** and **Sell** quote boxes (`—`). On trigger: **Buy** locks at the trigger Buy (latched fill look — colored background, locked price + live Ask beside it) and stays **disabled**; **Sell** is the only active control with a live Bid. With **Trade Off** this is visual/sim only; with **Trade On** the same moment places the real Buy, and with Sell **FAK/FOK** a Sell at Profit places the real Sell (with Sell **GTD** the limit rests at fill + Profit as soon as Buy fills). **Right** when Sell reaches **buy fill** (or trigger Ask if no fill) + **Profit prediction (¢)** — Sell latches with a ✓ next to the price briefly, then both reset. **Wrong** at window end shows an ✕ on Sell for the same brief time, then both reset. After a **Right**, if time remains in **Trigger Area**, the detector can fire again. Each trigger also adds a **Prediction UP/DOWN** card in **Positions**. Click ⓘ for the Gap vs UP/DOWN Buy trigger note (works when Prediction is Off too; does not reveal settings) |
| **Right / Wrong** | Per-series counts updated when each prediction is scored by Profit prediction (including re-triggers after Right and background parked predictions). **Reset** clears both counts for the selected market |

**Trigger:** while Gap stays the same or stronger in its direction, UP Buy gets cheaper and DOWN Buy gets more expensive (mirror for a negative Gap). **On top of that**, when Duration starts the cheapening Buy must be between **Min Quote (¢)** and **Max Quote (¢)**, and over Duration it must drop by at least **Shift (¢)**. On trigger, the price graph container border turns **green** for Prediction UP or **red** for Prediction DOWN, and stays until the window ends. **Score:** after the buy (actual fill when Trade buys; trigger Ask when Trade is Off), Sell (Bid) must reach that buy price + **Profit prediction (¢)** anytime before window end — not whether that side wins the market.

Feed **Latency** is shown in the Settings page header. **Fill success** lives under Settings → **Stats**. See [Settings & wallet](doc:settings).

**Available markets**, **Recording**, and per-series **retention** are managed in the separate **Admin CRM** (not in this trader UI). Only available series appear in the market picker; trading APIs reject unavailable series. Recording still runs only on non-`TRADING_EXECUTOR` processes. On the recorder, stalled Chainlink (~20s) discards the active window and reconnects; a broader silence watchdog (~60s with no book/Chainlink ticks) reconnects feeds and restarts that series’ recorder. See [Information flow](doc:data-flow).

Scheduled live: **Allow trade** + **Auto Trade** + **Use Schedule** on.

Edit phases on the chart: **Auto Trade** on, **Use Schedule** off.

## Chart and phases

Shows PTB, price, gap, and **3 phases** for the active setup. Click a phase band to edit when editable.

| Mode | Source of phases | Editable on chart? |
|------|------------------|--------------------|
| Auto Trade on, Use Schedule off | Graph setup | Yes |
| Use Schedule on | Schedule setup for current UTC slot | No — edit on [Schedule](doc:schedule) |

## Quotes, positions, triggers, log

Left-column sections (Wallet, Trade, Positions, Triggers, Log) share resizable headers — drag a section header to grow or shrink the panels above and below. When the left column is covered, the rail shortcuts reopen Trade, Positions, Triggers, or Log.

- Up/Down quotes; click to place manual orders when trading is armed (order type from Trade → **Manual Override**)
- Live and Demo position cards (buy times in UTC). On held settlements, **Market** / Win / Loss settle on the same official outcome clock as Prediction (completed crypto-price, else explicit Gamma — no extra portfolio wait); Win/Loss is whether your bet side matched that outcome. Portfolio marks may refine P/L dollars after that, never decide the outcome alone
- **Prediction** cards (when the detector triggers): labeled **Prediction UP/DOWN** (not Bet). Shown in **Live** always, and in **Demo** while Prediction is **On**. Rows are Trigger time, **Buy** (trigger Ask, or actual fill price/shares when Prediction Trade succeeds), **Target** (buy fill — or trigger Ask if no fill — + **Profit prediction (¢)**), and Source (**Pending…** / Confirmed) — no Market or P/L. After Profit prediction scoring (Right when Sell hits target, Wrong at window end), status shows a ✓ or ✕; when **Trade** was **Off** for that trigger, **Sim** appears to the left of the icon. Cards persist across refresh. Trigger Area Sell briefly shows the same ✓ / ✕ next to its price before resetting
- **Triggers** — list of created detector triggers for the workspace (definitions + Demo mode/pause/demo stats saved per signed-in user in Mongo — edit on prod or local and the same cards sync). Each card shows its **Title**, a **Demo** / **Trade** switcher (default **Demo**), a **Pause** / **Active** toggle (default **Pause**), then a visual-only **BUY** / **SELL** row (50/50, not clickable): on a buy, the left **BUY** cell highlights green (UP) or red (DOWN) with side, price, and shares until exit or window end; if it sells (take-profit / stop-loss), the right **SELL** cell briefly shows sell price/shares in the same UP/DOWN color as the buy (buy stays visible), then both clear so the card looks re-armed. Below that: **Stop Loss** exit-reason count, then green/blue/red dots (**Success** / held win / **Fail**) with P/L for the selected mode, and a **⋮** menu with **Edit** / **Delete**. In **Demo**, a reset icon (same as Live header stats) sits to the left of those counts and clears that card’s Demo stats (confirm first). **Trade** mode has no Reset — live totals stay. Green = profitable Take Profit exit (no separate Take Profit count on the card); blue = held win; red = fail/loss. Fees can still make a Take Profit exit count as Fail. Switching **Demo** / **Trade** also switches which stats the card shows: **Demo** stats are stored on the card (Mongo); **Trade** stats are the all-time live totals from the server, credited only when a real Trigger Trade position card settles the same way as phase cards (sold fill or official held outcome) — not from client-side guesses. **Pause** (vs **Active**) stops evaluation entirely and, if the card was on **Trade**, switches it back to **Demo**. Only when **not paused**: **Demo** simulates fills and updates success/fail/take-profit/stop-loss/P/L on the card; **Trade** places real orders only on the production trading host (requires **Allow trade**), overrides phase Auto Trade for that window while the trigger position is open, and records **Trade** success/fail/take-profit/stop-loss/P/L on the server (Mongo) from that same settled position card (sold fill or official held outcome — not a client-side flat guess). Localhost can edit cards and run **Demo**, but does not place Trigger Trade orders. Turning **Allow trade** Off moves every **Trade** card to **Demo**. If Trade is selected while Allow trade is already off (or the host cannot execute), the card stays on Trade but does not place orders or collect Demo stats. Schedule **Live** shows Trade+Active Market Triggers in the setups-column footer (read-only; same Trade stats). **Trigger Trade** fills attribute to the Live week placement covering that window (Schedule cards + Schedule total) whenever such a placement exists — **Use Schedule** is not required (that switch only picks the phase setup for Auto Trade). Schedule **Replay Triggers** stay browser-local and are separate from Market Triggers. **Create Trigger** opens the dialog; **Create** (requires a **Title**) adds a **Paused** / **Demo** card. Dialog tabs: **BUY** / **SELL** / **Stats**. **BUY** holds the duration diagram with two fixed vertical bars. Each bar is a **0–100¢** price scale (bottom = 0, top = 100). Both bars are **BUY** (Ask) only — there is no SELL Price quote mode. **Left (start):** **Range** (min/max ¢ band, two dots) or **Price** (one dot on an absolute **0–100¢** scale — bottom = 0, top = 100); Range arms when Ask is in the band, Price when Ask equals that ¢. **Right (end):** **BUY Price Range** or **BUY Price Change** (signed ±¢ from Duration start — e.g. +20 rise at least 20¢, −50 fall at least 50¢, **0** = unchanged). **Duration 0** disables the right bar and the right half of the center diagram (end price + end gap + trend wheel) — only the left **Range**/**Price** and left gap apply, and the trigger fires immediately with no wait. At the top of the BUY tab, **Buy order type** is `FAK` / `FOK` / `GTD` (default **FOK**). **GTD** is enabled only when Duration is **0** and the left bar is **Price**: at Apply-window start (wall clock; full Apply = market-window start) it posts a resting limit buy at that ¢ without waiting for a quote/tick (**+ Gap** → UP only while the gap matches; **− Gap** → DOWN only while the gap matches; gap flip cancels the rest; **no gap** → both UP and DOWN, first fill cancels the other). After a GTD fill the card rearms. Same rules apply in Schedule **Replay Triggers**. Borders stay green for BUY. A gold dashed **PTB** line always runs mid-height across the diagram. A placeholder zigzag market-price line appears only when a gap is set on at least one side. Top/bottom gap buttons on each side set an optional market-vs-PTB requirement: top **+ Gap** = market above PTB (green fill), bottom **- Gap** = market below PTB (red fill). The zigzag sits above or below the mid PTB line for that half; enabling the same gap direction on the other half continues on that same side without moving the first half. Only opposite start/end directions make the line cross PTB mid-span. Each active half’s band between PTB and the price line fills and the price line is colored the same red/green; both sides active cover the full width. Each active gap has **Min** / **Max** + a dollar size (0 = any gap size), shown on the opposite side of the PTB line from the gap fill. Clicking the active gap button clears that side. When **both** halves use the **same** gap side (+/+ or −/−), a **trend wheel** appears on the PTB mid-point: spin the two-sided handle (or type the center value) for the signed **market-price change over Duration** in dollars, with **Min $ Change** / **Max $ Change** centered under the wheel for +/+ gaps, or above the wheel for −/− gaps — on top of the gap-size filters. Example: **+20 Min $ Change** = asset must rise at least $20 from Duration start; **−40 Max $ Change** = asset must fall, by at most $40. Default is **Min $ Change** at **0**, which has no effect. The zigzag slopes to preview that change (larger |$| = steeper). The wheel is hidden when gaps are unset or on opposite sides. Left bar = start Range or Price; right bar = end Range or Price Change. A timeline runs along the bottom between the bars; next to **Start** is **Shares** (1–100000, default **10**) for the buy size; the right end has a duration value + unit (**ms** / **sec** / **min**), and **0** means no Duration (immediate fire on start). Buys use the selected **Buy order type** (**FOK** = full size or no fill; **FAK** may partial-fill) and only take Asks **at or below** the end band high (or the start Price / start band high when Duration is **0**, Buy **GTD**, or end mode is Price Change) — they do not walk the book above that cap. Below that, **Apply window** is a horizontal bar with two draggable dots for the portion of the market window when the trigger may fire (same 0→window-end time scale as Prediction **Trigger Area**; defaults full window). **SELL** has **Sell order type** `FAK` / `FOK` / `GTD` (default **FAK**), plus **Take Profit (¢ from fill)** and **Stop Loss (¢ from fill)** (1–100 each; defaults **10** / **10**) — Bid must rise or fall that many ¢ from the **buy fill** (not absolute quote prices). **100** disables that exit (never sell on that path). If neither TP nor SL hits before window end, the position is held to the market outcome: **blue** on the Trigger card when the buy side wins, **red** when it loses (green still means a profitable Take Profit exit). If the Trade position goes **flat earlier** (manual sell, or any other full exit), the card records that sell with the **actual exit price / P/L** (green or red) — it does **not** later count a held blue/red at $1/$0. With Sell **GTD**, a resting limit sell is placed at **fill + Take Profit** as soon as the Buy fills (does not wait for Bid; skipped when Take Profit is **100**). With Sell **FAK**, exits retry until the position is flat; **FOK** retries on later ticks if the order does not fully fill. Stop-loss or window-end with a resting GTD cancels it and sells **FAK**. After a full exit the card may fire again in the same window if conditions rematch. **Stats** shows all-time **Trade** Take Profit / Stop Loss on one row, then green/red Success/Fail counts with P/L on the next collected across live sessions for that card (server only — not Demo). Runtime (deployed host): while unpaused and inside Apply window — **Buy GTD** (Duration **0** + left **Price**) posts the resting limit on Apply-window start by wall clock (full Apply = market-window start) without waiting for a quote/tick, then rearms after fill; otherwise when an UP or DOWN Ask matches the start **Range** band or exact start **Price** (+ optional start gap): if **Duration** is **0**, it opens a position immediately (end price/gap/trend ignored); otherwise it watches for **Duration**, then requires the end condition (+ optional end gap); on match it opens a position and exits on take-profit, stop-loss, or window end. On a **Trade** buy (or a **Demo** buy while **Allow trade** is Off), the price graph shows one filled **dot** at the buy moment (green for UP, red for DOWN — the same single buy/sell dots used for phase and other fills; never a double marker) and a light matching **full-height** Duration band (fill only, no border) covering the Duration window that led to that buy; markers clear when the market window rolls. **Demo** still collects local stats while **Allow trade** is On, but does not draw those graph markers
- Log of bot / order activity (manual quote clicks log submit / placed / ignored / failed)

**Header Market P/L** is the sum of settled trade results for the selected series (fees included), including **manual** and auto/schedule trades. Manual wins/losses count here and in **Live**, but not on [Schedule](doc:schedule) cards or the Schedule total. The wallet balance is your current USDC cash — it only matches Market P/L after accounting for deposits/withdrawals, and only once losing tokens are resolved and winning tokens are redeemed into USDC. Polymarket usually auto-redeems wins; worthless losing tokens may still show as “redeemable” dust (~$0). Settled held trades count once the official outcome is known (completed crypto-price, else explicit Gamma).

Fees: when Polymarket’s trade feed includes the USDC notional, the app uses that for an exact fee; otherwise it estimates from the market’s taker fee curve.
